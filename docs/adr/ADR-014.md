# ADR-014: Evolution & Horizontal Scale Seams (1,000 to 100,000+ Users)

## Status
Accepted

## Context
The architecture must cleanly scale from a single campus deployment (1,000 users) to a multi-campus enterprise (100,000+ users) without rewriting core domain code.

## Considered Options
1. Premature distributed microservices architecture
2. Hexagonal Modular Monolith with pre-engineered horizontal scale seams

## Decision
Adopt **Pre-Engineered Horizontal Scale Seams**.
- Stateless backend pods behind load balancer using signed JWTs.
- Redis Pub/Sub backplane for distributed SSE fanout across instances.
- Range partitioning on `incident` and `audit_record` tables by month (`created_at`).
- Outbox pattern over Kafka for external event streaming.
- Multi-tenant tenant isolation via PostgreSQL Row-Level Security (RLS).
