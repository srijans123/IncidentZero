# ADR-006: Domain Model: Roles, Capabilities & Categorization

## Status
Accepted

## Context
Proper object-oriented modeling of campus user roles, technician capabilities, and incident categories must follow Open/Closed principles without fragile inheritance trees.

## Considered Options
1. Subclassing `Incident` by category (rejected: re-diagnosis alters object identity)
2. Subclassing `Technician` by support tier (rejected: promotes rigid hierarchies)
3. Inheritance for polymorphic permissions; composition for capabilities; data profiles for categories

## Decision
Adopt **Inheritance for User roles, Composition for Technician capabilities, and Data Profiles for Categories**.
- User hierarchy: `Employee`, `Technician`, `Administrator`.
- Technician capabilities are composed via skills, load capacity, and availability shifts.
- Categories are modeled as data (`CategoryProfile`), enabling re-diagnosis without mutating object identity.
