# ADR-009: Technician Allocation & Hungarian Batch Assignment

## Status
Accepted

## Context
Under ticket storms (e.g., 40 simultaneous reports), greedy single-ticket dispatch causes technician overloading and race conditions.

## Considered Options
1. Pure sequential greedy dispatch (sub-optimal global load distribution)
2. Exact branch-and-bound ($n \le 7$) + Multi-pass Kuhn-Munkres ($n > 7$) in `HungarianBatchAssigner`

## Decision
Adopt **Hungarian Batch Assignment with Atomic SQL Capacity Reservation**.
- Dispatches batches maximizing total assignment utility while respecting capacity ceilings.
- Enforces <= 1 P1 incident per technician.
- Atomic SQL `UPDATE technician_load SET points = points + :w WHERE points + :w <= capacity` eliminates race conditions.
