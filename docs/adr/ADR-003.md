# ADR-003: Persistence & Search Strategy (NeonDB PostgreSQL + pgvector)

## Status
Accepted

## Context
The system must persist relational entities (incidents, users, SLAs), cryptographic audit logs, full-text lexical indices, and 384-dimensional dense semantic embeddings within a single ACID transaction boundary.

## Considered Options
1. Standalone Document Store (MongoDB) + Vector DB (Pinecone) (dual-write inconsistency risk)
2. NeonDB Serverless PostgreSQL with `pgvector` and `pg_trgm` (GIN)

## Decision
Adopt **NeonDB Serverless PostgreSQL with pgvector and pg_trgm**.
- Single ACID transaction encompasses incident state, audit ledger, and embeddings.
- Reciprocal Rank Fusion (RRF) combines BM25 lexical ranking and cosine vector distance in a single SQL query.
- Configured with `prepareThreshold=0` for connection pooling safety.
