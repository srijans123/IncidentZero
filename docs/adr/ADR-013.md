# ADR-013: Authentication, Authorization & Cryptographic Audit Ledger

## Status
Accepted

## Context
All actions must be authenticated, authorized via role-based access control (RBAC), and immutably recorded in a tamper-evident audit ledger.

## Considered Options
1. Mutable audit log table without cryptographic chaining
2. SHA-256 hash-chained audit ledger with canonical JSON payloads and database permission locks

## Decision
Adopt **SHA-256 Hash-Chained Audit Ledger with Canonical JSON**.
- Passwords hashed with Argon2id; stateless JWTs for API access.
- `audit_record` stores per-incident sequential SHA-256 hashes.
- Lexicographically sorted canonical JSON prevents false tamper alarms.
- `REVOKE UPDATE, DELETE` on `itsm_app` role ensures append-only storage.
- Admin verification endpoint checks hash integrity and pinpoints altered row IDs.
