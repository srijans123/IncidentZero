# ADR-002: Architectural Pattern: Hexagonal Modular Monolith

## Status
Accepted

## Context
The project needs clear bounded contexts and modularity without the operational and deployment complexity of distributed microservices.

## Considered Options
1. Distributed Microservices (rejected due to network latency, distributed transactions, and DevOps overhead)
2. Traditional Layered Monolith (rejected due to leaky abstractions and tight coupling)
3. Hexagonal Modular Monolith with Spring Modulith

## Decision
Adopt **Hexagonal Modular Monolith with Spring Modulith**.
- Modules communicate strictly through exposed api packages (`@NamedInterface("api")`).
- Domain core is protected from frameworks (Hexagonal Ports & Adapters).
- Verified at build-time with ArchUnit (R1-R9) and `ApplicationModules.verify()`.
