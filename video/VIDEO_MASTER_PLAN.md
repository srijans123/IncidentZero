# VIDEO_MASTER_PLAN.md — IncidentZero 20-minute demo video (fully automated, zero cost)

> **Audience: the coding agent (Antigravity).** Read this whole file before doing anything.
> Put this file at `video/VIDEO_MASTER_PLAN.md` and the course brief PDF at `video/00_brief/`.
> Work phase by phase. Do not start a phase until the previous phase's **GATE** passes.
> Every phase must be re-runnable (idempotent) and cache its outputs.

## 0. Goal and hard constraints (from the course brief)

Produce one MP4 that is the group's recorded project presentation for the OOP course project
"Intelligent IT Service Management & Incident Resolution System (I-ITSM)".

Hard requirements taken from the brief:

1. **Length: 15–20 minutes.** Target **19:00–19:30**. Hard fail if outside **15:00–19:55**.
2. It must be a **demo of the working application** and show **at least three complete workflows**:
   - W1: Employee reports → system classifies/prioritizes → technician assigned → notification generated.
   - W2: Technician investigates → SLA monitored → incident resolved → user notified.
   - W3: Multiple incidents reported → duplicates/related incidents identified → correlated/escalated.
3. **Every group member introduces themselves and explains the functioning of at least one module.**
   Real members record these clips (see §9). The pipeline must have reserved slots for them. Never
   silently replace a member with a synthetic voice; if a clip is missing, flag it in `QA_REPORT.md`.
4. It must cover, with evidence from the real running app/code, everything the rubric rewards:
   problem analysis, architecture, tech-stack justification (the 9 questions in the brief),
   UML (use case + class), DB design (ER, schema, sample data), OOP principles, **≥2 design patterns**,
   exception handling, security (authN, RBAC, password protection, validation), SLA management,
   **≥2 assignment strategies**, **≥2 notification mechanisms**, audit trail, **≥5 search filters**,
   dashboards/reports, **≥2 intelligent features**, **≥15 documented test cases**, innovation items.
5. Final file name: `<GroupNo>_OOP_S1_2025-2026_Project.mp4` (use the brief's literal pattern).
   Read `GROUP_NO` from `video/config.json`; if it is empty, stop and ask the user.

**Budget: ₹0.** Only free/open-source tools and free API tiers. No paid service, no trial that needs a card.

**Truth rule (most important).** The video is graded on real functionality. Narration may only claim
something that you verified exists in the code AND (for UI features) saw working in a capture run.
If a required feature is missing or broken, do not paper over it — list it in the coverage matrix (§Phase 1)
and stop for the user.

## 1. Tool stack (all free)

| Job | Tool | Notes |
|---|---|---|
| Thinking, coding, script writing | **Antigravity's own agent model** | No extra API key needed. |
| Voice-over | **Kokoro-82M TTS** (Apache-2.0, CPU-friendly) via `kokoro` or `kokoro-onnx` | Fallbacks in order: Piper → `edge-tts` (free, no key, but an online Microsoft service, not open-weight). |
| Word-level timestamps for captions | **faster-whisper** (`small` or `base`, CPU) | Used only to time known text; the script text is the source of truth. |
| Screen capture | **Playwright (Chromium)** driven by scripts you write | Deterministic, retakeable. Do NOT use the Antigravity browser subagent for final footage (see §Phase 5 note). |
| Sprite/mascot | **Generated by code** (pixel grids → PNG sprite sheets with Pillow) | Match the site's own look: read `DESIGN.md`, `landing.html`, `frontend/` for palette, fonts, any existing mascot. |
| Diagrams | **mermaid-cli** (class, use-case-like, ER, architecture) generated from the REAL code/schema | UML diagrams are graded deliverables; build them from source, not from imagination. |
| Editing/compositing | **Remotion** (React, renders MP4 locally) | Alternative if its licence is a problem for the team: Revideo (MIT). |
| Music + SFX | **Synthesised in code** (numpy square/triangle/noise → WAV) + the site's own SFX files if present | Avoids all copyright issues. |
| Final encode | **ffmpeg** | H.264 + AAC, 1920×1080, 30 fps. |

Optional external LLM (only if you want a second opinion on narration): use any **free-tier OpenAI-compatible
endpoint** hosting an open-weight model. Read `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` from `video/.env.video`
(gitignored). Never hard-code model IDs (free model IDs expire); if the variables are empty, skip this step.
The pipeline must work with no external LLM at all.

Machine: the user is on **Windows**. Use cross-platform paths, no bash-only scripts; provide `.bat`/Python entry points.
Assume **no GPU** unless detected.

## 3. Phases (each ends with a GATE)

### Phase 0 — Environment smoke tests
- Check Node ≥ 20, Python ≥ 3.10, ffmpeg on PATH, Playwright Chromium installed, Remotion installed.
- Smoke test each tool end-to-end with a 2-second artifact: 1 sentence of TTS → wav; 2-second Playwright
  recording of `landing.html`; 2-second Remotion render combining both.
- **GATE:** all three smoke artifacts exist and play. Record versions in `01_facts/env.md`.

### Phase 1 — Ground truth from the repo
- Read: `PRD.md`, `PRODUCT.md`, `DESIGN.md`, `progress.txt`, `incident_zero_*.md`, `docs/`, `backend/`, `frontend/`,
  `ml/`, `deploy/`, `scripts/`, `tools/`, tests, DB schema/migrations, `landing.html`.
- Start the app with the repo's own scripts (`start.bat`, `run_backend.bat`, `run_frontend.bat`). Fix nothing in
  product code unless the user asks; just record what happens.
- Write `01_facts/facts.json`: pages/routes per role (Employee, Technician, Admin), API endpoints,
  entities, lifecycle states and allowed transitions, assignment strategies, notification channels,
  intelligent features, design patterns **with class names and file paths**, custom exceptions,
  auth method, DB engine + schema, test files + test count.
- Write `01_facts/requirements.json` from the brief PDF (every MVP item, every deliverable, every rubric line).
- Write `01_facts/coverage_matrix.md`: each requirement → `PRESENT | PARTIAL | MISSING` + evidence (file path / URL / UI state).
- **GATE (human checkpoint):** show the user the coverage matrix. If anything is `PARTIAL`/`MISSING`,
  say so plainly and wait for instructions. Never script a claim for a non-`PRESENT` item.

### Phase 2 — Deterministic demo environment
- Create `04_capture/seed.py` (or equivalent) that loads demo data: ≥ 6 technicians with different skills and
  workloads, ≥ 8 services (include the brief's "payment application"), SLA policies for P1–P4, ≥ 40 historical incidents,
  a few near-duplicate incidents for W3, and some **pre-aged incidents** so SLA warnings/violations are visible
  immediately (do not wait in real time for 30-minute SLAs). Add a visible "demo data" note in the video's narration.
- Create `04_capture/reset.py` that restores the DB to the seed state in under 10 seconds.
- Create one test login per role.
- **GATE:** run reset → seed → open each role's dashboard headlessly → screenshots of all three look correct.

### Phase 3 — Storyboard and script
Write `02_script/storyboard.json` (schema in §4) and `02_script/narration.md`.

Time budget (total **19:20**; shift ≤ 15 s between acts if needed):

| Act | Content | Target |
|---|---|---|
| 0 | Cold open (problem in 20 s) + title card with group no., project, course | 0:40 |
| 1 | Team introductions — **real member clips** + lower-thirds | 1:30 |
| 2 | Problem analysis: stakeholders, challenges, proposed solution, assumptions; lifecycle Report→Close | 1:20 |
| 3 | Architecture, tech-stack justification (the 9 questions), DB design + ER, scalability | 2:15 |
| 4 | OOP design: class diagram; encapsulation, abstraction, inheritance, polymorphism, interfaces, composition; design patterns as real code cards; exceptions; collections | 2:45 |
| 5 | **Workflow 1** live demo | 2:30 |
| 6 | **Workflow 2** live demo (incl. SLA warning/violation) | 2:30 |
| 7 | **Workflow 3** live demo (duplicates, correlation, escalation chain) | 2:15 |
| 8 | Admin console: users/services/SLA config, strategy switch without redeploy, ≥5 search filters, dashboards, audit log | 1:30 |
| 9 | Security, error handling (e.g. NEW→CLOSED blocked), tests (run the suite, show ≥15 cases) | 1:10 |
| 10 | Innovation features, lessons, next steps, credits | 0:55 |

Script rules:
- Plain, friendly explainer voice. Define every acronym once (SLA, P1, RBAC…). 2,300–2,600 spoken words total.
- Each act opens with one sentence of "what you'll see" and closes with one sentence of "why it matters".
- **A visual change at least every 8–12 seconds** (cut, zoom, callout, sprite entrance, diagram step). No scene longer than 45 s without one.
- No more than two consecutive scenes of the same `mode`.
- Every scene has an `evidence` field pointing to a file path or a captured UI state. No evidence → scene is not allowed.
- Reserve an intro slot per member in Act 1, and one "own module" slot per member inside Acts 3–9 (lower-third: name + module).
- **GATE:** estimated duration (words ÷ 2.5 per second + pauses) inside 17:30–19:30; every `requirements.json` item has ≥ 1 scene;
  all three workflows present with every step from the brief.

### Phase 4 — Voice and timing
- Audition three English Kokoro voices on one paragraph; choose the clearest. Save the choice in `config.json`.
- Generate one WAV per scene (split long text at sentence boundaries). Add a pronunciation map for jargon
  (e.g. "I-ITSM", "SLA", "INC1024", "P1") using phonetic respellings.
- Normalise loudness to about −16 LUFS with ffmpeg `loudnorm`.
- `ffprobe` each WAV → `03_audio/timings.json` (`scene_id`, `start_s`, `end_s` on a master timeline, including 0.3–0.6 s breaths).
- Run faster-whisper on each WAV for word timestamps → `words.json` and `captions.srt`.
- **GATE:** no scene silent or clipped; total voiced duration + member clips + title/transition time lands in 15:00–19:55.
  If over, trim script text and regenerate only changed scenes (cache by text hash).

### Phase 5 — Capture (screen recordings done by scripts)
Build the capture engine **after** audio exists, so footage is timed to the voice.

- Playwright Chromium, viewport 1920×1080, deviceScaleFactor 1, one recording per workflow.
- Runner input: the scenes of that workflow with their master-timeline start times from `timings.json`.
  The runner executes each scene's `actions[]` scheduled at that scene's start offset and idles between actions,
  so the raw clip lines up 1:1 with the narration.
- Action vocabulary (implement as helpers): `goto`, `login(role)`, `moveTo(selector)`, `click(selector)`,
  `type(selector, text, wpm)`, `scrollTo(selector|y)`, `hold(ms)`, `pressKey`, `waitFor(selector|text)`.
  Humanise: eased mouse paths, 60–120 ms per keystroke with small jitter, 200–400 ms hover before clicks.
- Headless recordings show no cursor: **inject an overlay** (cursor arrow, click ripple, focus ring) via
  `page.addInitScript`, driven by the same coordinates the runner uses.
- Before every pointer action call `locator.boundingBox()` and append `{t_ms, scene_id, selector, label, x, y, w, h}`
  to `04_capture/boxes/<workflow>.json`. **This file is what lets the sprite and zooms point at the exact element.**
- Quality: compare Playwright's built-in `recordVideo` against CDP screencast frames; keep whichever is sharper at 1080p;
  re-encode with a high bitrate.
- Take a PNG screenshot at the end of every scene into `04_capture/shots/<scene_id>.png` (also used as fallback stills).
- Capture the terminal-style scenes (test suite run, `git log`, seed script) with a styled terminal renderer inside
  Remotion from real command output you saved — do not film a real terminal window.
- Anything that fails twice: retry with simpler selectors; after 3 failures, mark the scene `NEEDS_HUMAN` in the report and continue.
- **Note on the Antigravity browser subagent:** it records sessions automatically, but it is an autonomous one-shot LLM
  agent with no frame-accurate timing. Use it only to explore the UI or debug a selector, never for final footage.
- **GATE:** every capture clip's duration matches its timeline slice (±0.3 s); every scene with a pointer target has a bbox entry;
  no secrets (`.env`, tokens, keys, personal data) visible in any frame — scan the screenshots.

### Phase 6 — Sprite (explainer character)
- Name: **Zero** unless the site already has a mascot (check `DESIGN.md`/frontend assets; reuse and extend it if so).
- Draw with code: 48×48 or 64×64 pixel grids defined as character matrices + a palette taken from the site;
  export nearest-neighbour upscaled PNG sprite sheets.
- Required poses: `idle` (with blink), `talk_closed`, `talk_half`, `talk_open`, `point_left`, `point_right`,
  `point_up`, `point_down`, `think`, `wave`, `celebrate`, `alert` (for SLA breach / critical), `shrug`.
- Lip-sync: choose `talk_*` frames from the scene WAV's RMS amplitude per video frame.
- Entrance/exit: pop-in from a screen edge with squash-and-stretch (spring), exit with a pixel-dissolve.
- Pointing logic: the sprite sits at the screen edge **opposite** the target, never covering the bbox; a dotted laser line
  runs from its hand to the bbox centre and a pulsing ring wraps the bbox. Speech bubble shows 3–8 words max
  (the key phrase), not the full sentence.
- **GATE:** contact sheet of all poses at 1×; one 5-second test clip where Zero enters, points at a bbox from `boxes/`, and exits.

### Phase 7 — Music and SFX
- Synthesise three looping chiptune beds (calm, tense, triumphant) and an SFX pack
  (click, pop, whoosh, ding, alarm, typewriter, error buzz). Reuse the site's own SFX if it ships any.
- Music sits at about −26 dB relative to voice and **ducks** a further 6–8 dB while the narrator speaks.
- **GATE:** a 10-second mix test with voice + bed + two SFX; no clipping.

### Phase 8 — Remotion composition (the "professional edit")
1920×1080 @ 30 fps. Build these components and drive them entirely from `storyboard.json`, `timings.json`,
`words.json`, `boxes/*.json`:

- `ScreenScene` — plays the raw clip slice; **zoom/pan to the target bbox** (1.5–2.2×, ease-in-out, hold, ease-out).
- `SpriteExplainer` — Zero entrance, lip-sync, pointing line, ring, bubble.
- `DiagramScene` — mermaid SVGs revealed step-by-step (nodes light up in sync with narration).
- `CodeCard` — syntax-highlighted excerpt of a **real** file with the key lines highlighted (patterns, state machine, strategy classes).
- `TerminalCard` — styled replay of saved command output (tests passing, seed run).
- `ChapterCard` — act title with progress dots "Act 3 / 10".
- `LowerThird` — member name + module, or feature label.
- `Callout` — pixel arrow + label on arbitrary coordinates.
- `Captions` — bottom captions with the current word highlighted.
- `MemberClip` — letterboxed real clip with name lower-third; if the clip is missing, show a clearly marked placeholder card.
- Transitions: hard cut (default), whip-pan, pixel-dissolve wipe, match-cut on zooms. Vary them; no two identical transitions in a row.
- Audio: voice track, music bed with ducking, SFX on cuts/clicks/alerts.
- Add a 1-second end card with the group number and project name.

Preview renders: `--preview` renders 960×540 @ 15 fps for fast checking. Final render: full quality, concurrency tuned to the CPU.

### Phase 9 — Render and QA (automated, then report)
1. Render `08_out/final.mp4` (H.264, AAC, CRF ~18–20) and a smaller `final_720p.mp4` for upload if the shared-folder size limit is unknown.
2. `ffprobe`: duration within **15:00–19:55**; audio loudness about −16 LUFS; no clipping.
3. Extract one frame every 5 s into `08_out/contact_sheet/`. Look at them yourself and check: no blank/black frames (except intended),
   no overlapping text, sprite never covers its target, nothing cut off, no secrets visible.
4. Verify captions are within ±150 ms of speech at 10 random points.
5. Verify the three workflows each appear in full, and that every requirement in `coverage_matrix.md` marked `PRESENT` has a scene.
6. Write `08_out/QA_REPORT.md`: duration, scene count, requirement→scene map, any `NEEDS_HUMAN` items, any missing member clips, known weaknesses.
- **GATE:** QA report shows zero blocking issues, or lists them clearly for the user.

## 5. Human touchpoints (keep to the minimum)

1. **After Phase 1:** the user reads the coverage matrix (≈ 2 minutes).
2. **After Phase 3:** the user may skim `narration.md` (optional; the agent proceeds if told "no approval gates").

Everything else runs unattended. If a phase fails, fix it, log the fix in `video/BUILD_LOG.md`, and continue.

## 6. Member clips (to be recorded by real people)

Each member records one vertical-or-horizontal clip of 20–45 seconds covering:
name, role, and a spoken explanation of **their own module** (what it does, one design decision).
Put the files in `video/00_members/` and set `clip_path` in `config.json`. The pipeline should:
- accept any common video format, auto-crop/letterbox to 16:9, loudness-normalise, add the lower-third;
- display the matching real screen footage of that module behind or beside the clip (picture-in-picture) so it still feels designed.

## 7. Failure and fallback rules

- TTS too slow or fails → switch voice engine in the fallback order; keep going.
- Selector flakiness → add waits, then simplify; never film a broken state.
- Remotion render too slow → lower concurrency / render per act and concatenate with ffmpeg.
- Total over 19:55 → shorten Acts 3–4 narration first (never cut a workflow step).
- Total under 15:00 → add `why it matters` beats and slower zooms; do not pad with silence.
- Licence concern with any tool → say so in `BUILD_LOG.md` and use the listed alternative.
